# feat: 完善上下文工程、自动记忆与交互式终端

长对话原先缺少统一上下文预算与可追溯的压缩流程，工具输出截断可能造成不完整参数，记忆设置也缺少自动提炼链路。本次增加预算组装、任务状态、证据归档、工具完整性校验与候选记忆审阅，并将逐条命令面板升级为可持续交互的 PTY 终端。

## 主要变更

- ContextEngine 统一组装任务状态、相关记忆、历史与工具证据；按完整旧轮次压缩，保留最新要求及约束摘录，归档原文支持分页读取。子 Agent 仅接收任务相关上下文，证据按角色隔离。
- 预留模型输出预算；完整组装流式工具参数，检查完成标记和严格 JSON/schema，整批验证后执行。截断或参数错误有限重试，权限错误不重试。工具台账阻止同调用 ID 重复执行，中断标记结果不确定。
- 大文件先分块暂存，校验片段顺序、总长度、文件版本和权限后提交，保留缩进与换行。
- SQLite V009 将旧记忆设置迁移至独立记忆/版本表；支持全局和项目范围、相关召回、固定、归档恢复、来源与版本记录。
- 自动提炼默认关闭，开启后调用当前对话模型，从用户消息生成有原文来源的候选，经后端核验和用户接受后才生效。明确以“记住”开头的请求直接保存，避免重复确认。
- 增加设置中的上下文工程入口、记忆候选管理和对话中的上下文检查面板。
- 使用 pty4j + xterm.js 实现真实 Shell 输入、目录/环境保持、多会话、分屏、调整尺寸、搜索、重命名和刷新重连；Tauri 正常退出前清理终端。用户操作的本机终端不扩大 Agent 沙箱权限。

## 边界与发布注意事项

- Token 采用启发式估算；历史压缩为结构化摘录，非模型语义总结。必要内容仍超预算时明确停止。
- 自动提炼是原文候选，不能保证识别全部隐含偏好或敏感信息；候选需审阅，相关原话会发送至当前模型服务。
- 删除/归档停止后续召回，历史版本和快照仍保留；SQLite 证据暂未自动清理，极长会话历史分页仍待优化。
- 工具调用台账不保证跨外部系统 exactly-once；不同 ID 的语义重复仍需结合文件版本和执行结果判断。
- PTY 会话在服务重启时断开；macOS/Linux 原生终端与完整桌面安装包仍待实机验收。
- 详细设计与限制见 docs/context-engineering.md。本地数据库、密钥、日志、依赖目录和生成二进制不纳入提交。
