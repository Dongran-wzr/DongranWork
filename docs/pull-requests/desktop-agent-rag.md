# feat: 完善桌面 Agent 工作台、知识库 RAG 与隔离命令执行

原有桌面原型的任务、资料与开发工具缺少完整的业务链路，聊天还会直接显示 Markdown 源码。本次将前端接入按业务分层的 Spring Boot 服务，使任务可以根据意图读取项目、检索资料和网页，再生成带可定位引用的回答，并提供模型配置、Git 图形工作区和隔离命令执行。

## 主要变更

- 后端采用 Controller / DTO / Service / Repository 分层，补充请求校验、SQLite 迁移 V002–V008、统一错误响应、本机会话和系统凭据管理。
- 主 Agent 依据用户意图选择必要工具及专业角色；预先执行所需检索，不依赖模型是否主动调用工具。补充能力检测、审批、取消、执行记录和 SSE 输出。
- 知识库支持多格式导入及预览、片段定位与高亮；使用本地 SQLite 向量索引，Embedding / Rerank 由用户配置，向量不可用时降级 BM25。PDF 字形缺少 Unicode 映射时标记需 OCR，避免把乱码建入索引。
- 知识库问答筛选相关上下文并生成实质答案，在答案下方显示实际使用且通过校验的引用；只有引用没有答案时重试一次，仍不合格则报告失败。
- 接入 web_fetch / web_search，清洗查询并过滤 Bing RSS 无关结果；增加 Tavily / Brave 配置和连通性检验，密钥不进入普通偏好。
- 回复采用 marked + DOMPurify 渲染 Markdown，覆盖表格、标题、引用、列表、代码块及流式输出；保留知识库引用定位与平滑回到最新回答。
- 增加 Git 图形工作区、模型供应商管理、设置与业务接口联动，以及账户、记忆、调度、连接等业务代码。
- Rust 沙箱助手接入命令 API 和 Tauri 资源准备脚本。Windows 使用 AppContainer / Job Object，项目快照成功执行后检查冲突并回写；沙箱不可用时阻止执行。

## 验证

- 后端完整测试：90 项，0 失败、0 错误（本阶段已执行）；Markdown 前端变更后重新打包成功。
- `node prototype/verify-markdown.cjs`：Markdown 排版、表格、安全链接、HTML 注入过滤及未完成流式文本通过。
- `node prototype/verify-citations.cjs`：仅引用回复的补答、引用筛选、答案下方来源、预览高亮、滚动动画、历史位置保持、重启恢复及搜索设置保存通过。
- 本地服务重启后确认搜索配置 API 与静态资源可访问。
- 公开 Java 21 虚拟线程搜索实测发现 Bing RSS 在当前网络仍可能返回无关结果或超时；已过滤无关结果并提供搜索 API 替代入口，不把该测试记作搜索质量验收通过。

## 当前边界与发布注意事项

- 当前终端是逐条命令执行面板：无持久 PTY、运行中输入、跨命令的 cd / 环境变量保持；界面请求默认超时 120 秒，命令沙箱禁止联网。
- macOS 沙箱尚未启用；Linux 原生隔离及三平台完整安装包尚未完成实机验收。JVM 随包分发、托盘生命周期、签名和公证仍待完成。
- Tavily / Brave 已验证请求协议与结果映射，真实云端鉴权和额度仍需用户在应用中配置密钥后检验；不需要在 PR 或聊天里提供密钥。
- OCR 尚未接入；标记需 OCR 的 PDF 不应视为已完成可检索文本提取。
- 快照回写包含冲突检查，但不是整个变更集的原子事务；中途失败需检查项目差异和保留的快照。
- 本次未重跑完整 `verify-backend.cjs`（此前在 Git 暂存交互处出现不稳定）；不宣称已完成所有桌面流程验收。
- 升级会执行 SQLite 迁移，发布前应备份本地数据；本地数据库、密钥、运行日志、依赖目录和生成的二进制不纳入提交。
