# 上下文工程与自动记忆

本功能使用现有 Spring Boot 服务、SQLite 和用户配置的对话模型，无需额外本地模型或服务。

## 入口与默认行为

- 设置 → 上下文工程：自动历史压缩、输出预留、截断/参数修复重试次数、召回条数。
- 设置 → 记忆：启用记忆、自动提炼、全局与项目条目、候选接受/拒绝、固定、归档/恢复、版本与原文来源。
- 对话标题 → 本轮上下文：查看最近 30 次调用的预算、实际记忆、历史归档与证据，以及工具执行记录。
- 自动提炼默认关闭。开启后使用当前对话模型额外请求一次，从最近 8 条用户消息中提炼最多 3 条候选；不使用助手回答和工具输出作为来源。每条来源最多 1500 字符。
- “记住：以后统一使用中文回答”直接保存；在项目会话中默认保存到项目，以“全局”或“所有项目”开头则保存全局。明确指令只识别消息开头的“记住”，不对文档中的相似文本执行保存。

## 三阶段实现

### 1. 预算、状态与安全恢复

ContextEngine 为每次主/子 Agent 模型调用组装任务状态、相关记忆、历史和证据。预算包含输入、工具定义、输出预留和安全余量。输出默认预留 4096，实际不超过窗口的三分之一；余量为窗口的 5% 且至少 256。

超过预算时按较早完整对话轮次归档，保留最新用户请求；生成结构化摘录，包括用户约束、明确决策和近期请求摘要。大工具输出替换为证据引用，可用 read_evidence 分页重读。必要上下文仍超限时明确停止，不截断参数或静默丢弃已提取的约束。

任务状态单独持久化，主 Agent 可通过 update_task_state 维护计划、约束、决策、待办与摘要。子 Agent 仅收到分配任务、当前要求、共享目标/约束和自己的工具上下文；不能读取其他子 Agent 的证据或修改主任务状态。

流式工具调用先全部组装，再检查完成标记和严格 JSON/schema。length、意外 EOF、缺少工具完成标记不执行；参数校验失败整批不执行。默认最多重试一次并重新生成完整调用。权限拒绝不重试。

工具调用写入执行台账。相同任务/角色/调用 ID 不能重复执行；异常中断或重启时未完成调用标为 uncertain，模型应先查 execution_status 再检查实际产物。该台账不宣称实现外部系统 exactly-once；不同调用 ID 的语义重复仍依赖权限、文件版本检查和模型判断。

大文件使用 begin_file_draft → append_file_draft → commit_file_draft。单片最大 12000 UTF-16 字符，总计 200000；校验片段顺序、总片数、总字符数、已有文件 SHA-256 和写入权限，完成前不修改原文件。空白和换行原样保留。草稿持久化可追溯，应用退出不会自动提交。

### 2. 长期记忆

V009 将旧 memoryEntries 迁移为独立 memories/memory_versions 表。兼容旧设置接口；状态和内容修改留版本，删除为停用而非物理擦除。

召回仅使用有效状态和启用范围内的记忆；项目同名约定覆盖全局，固定条目优先，其他按查询词相关性排序。最多默认 8 条，并受 2500 估算 token 预算约束。归档、删除、拒绝与其他项目条目不参与后续召回；历史快照仍保留当时的使用记录。

自动提炼要求候选绑定真实用户消息 ID，quote 必须为该消息连续原文，content 必须等于 quote。过滤常见密钥/密码格式，去重并保留拒绝记录。候选接受后才能参与回答，同范围同标题不同内容需要先处理冲突。敏感数据过滤是启发式，不能保证识别所有秘密；审阅仍必要。

自动提炼失败只显示状态，不影响已经生成的回答。明确保存无需模型提炼。自动提炼和后续记忆召回会将相关用户原话发送给当前配置的模型服务，数据本身存储于本机 SQLite。

### 3. 可视化与可配置

上下文检查界面展示任务目标/当前请求、预算、实际选中的记忆及版本、压缩数量、可分页读取的归档，以及工具执行状态。记忆设置提供来源、接受/拒绝、固定/取消固定、归档、恢复和版本记录。

## 当前边界

- Token 为字符启发式估算，不是各服务商 tokenizer 的精确值；实际输出上限也可能低于配置。
- 历史压缩是可追溯的结构化摘录，不是另一模型生成的语义总结。模型维护的任务状态用于补充决策和进度；抽取规则不能保证识别所有隐含约束。
- 历史与证据完整保存在 SQLite，当前无自动过期清理策略；长时间使用会增加本地库大小。读取历史目前仍加载本任务的用户/助手消息，极长会话的分页优化尚未实现。
- 记忆召回使用本地词项相关性，不新增 embedding 请求；知识库向量检索不受影响。
- 记忆来源和版本可查，但旧版本恢复通过审阅后重新编辑实现，界面“恢复使用”恢复的是当前条目的状态。
- 桌面发布仍需在 Windows/macOS/Linux 各自验证打包。本轮测试为 Windows 本地环境，不代表另外两平台已验收。

## 验证

ContextEngineeringTest 覆盖预算/历史归档、约束保留、作用域与状态召回、旧设置不复活删除项、明确保存、自动候选来源校验、证据隔离、重复执行台账、分块草稿、完整 Agent 分块提交、旧数据迁移与严格参数验证。

ModelStreamIntegrityTest 使用本机 HTTP fixture 验证碎片工具参数拼接、length 拒绝、缺少完成标记和 EOF 拒绝。

prototype/verify-context.cjs 使用临时本地服务与合成模型验证提炼→审阅→固定→实际召回→归档、版本记录、设置刷新和上下文面板；verify-citations.cjs 回归 RAG 引用定位、预览安全和滚动动画。不会调用用户云端模型或发送用户文档。
